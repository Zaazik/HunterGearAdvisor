# Pre-raid set search (2026-11-16)

- `opt.py` — candidates: wowsims/forever `assets/database/db.json` (stats, pseudoStats, classAllowlist, factionRestriction, sources), filters for what a Horde hunter can get now (no raids, no Ony-head quest, no Watchers rep, no PvP rank, BoP crafts only of own professions; a craft's recipe item from the client DB2, its source from db.json when db.json lists it, else from the recipe's foreverdb.net page — db.json lists no recipe items; a craft none of whose recipes has a known source is dropped unless the recipe or the item was seen on the AH). Needs, next to `../taskA/forever` and `../trinkets` in the original scratchpad layout: wago DB2 CSVs (ItemSparse, ItemSet, ItemSetSpell, SpellEffect, Spell, ItemEffect, ItemXItemEffect; build 1.60.1.70888), `ah.tsv` from `ah.lua` (Auctionator's saved prices), `pattern_sources.tsv` from `gen_pattern_sources.py` (whose rule it also loads, from its own folder), ForeverGuide NewDungeonData.lua. A recipe it looks up with no row in `pattern_sources.tsv` is an error naming the ids to save.
- `python -I gen_pattern_sources.py [pages dir] [out.tsv]` — where each recipe item comes from by foreverdb.net: reads the saved pages `data/fdb/<itemID>.html` (`https://foreverdb.net/item/<itemID>`) and writes `data/pattern_sources.tsv`: itemID, state, text. State `known` (the "Where to get it" list, its items as text), `unknown` (the page says the source is not known) or `no page` (foreverdb.net's "Item not found" page; the client has no ItemSparse row for such recipe ids). Another page layout is an error. Tests: `tests/test_gen_pattern_sources.py`.
- `solve.py [hitCapRating] [comma-separated ids to drop]` — DP over slots with hit rating as state (hit above the cap is worth 0), set bonuses by forcing set pieces. Weights: wowsims Turret EP.
- `lua ah.lua <SavedVariables/Auctionator.lua> <out.tsv> [realm key]` — dumps the Horde auction prices Auctionator saved (`AUCTIONATOR_PRICE_DATABASE`, one house per realm key such as `PvP Horde`, a house as a table or as CBOR) to `ah.tsv`: itemID, price (copper), time (unix), count, gone — the columns `opt.py` and `rescore/avail.py` read. Price: the lowest last-scan buyout of the item's keys (`<itemID>`, gear `g:<itemID>:<item level>`); time and count: its newest day; gone: that day is older than the newest day of the house. The layout is the one Auctionator 349's code writes (the sources in the head of `ah.lua`), and the account's own `Auctionator.lua` of 2026-11-21 has it: `__dbversion` 8 and the one key `PvP Horde`, its house a CBOR string with 6819 items keyed `<itemID>` and the house's `version`; the tool reads it into 6819 lines. The file is read as bytes: its CBOR strings hold byte 0x1A, where a text-mode read on Windows stops. An item entry with no day is an error (Auctionator writes the day of each price it records). Without the realm key the only Horde one is read; several are an error that lists them.
Result and sources: `docs/research/preraid-bis-60.md`.
